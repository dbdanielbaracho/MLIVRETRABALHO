# REST contract

[openapi.json](openapi.json) describes the 106 currently registered operations in 43 NestJS controllers, with 38 JSON request bodies and 76 reusable schemas. It uses OpenAPI 3.1.0 and a relative server URL; it does not advertise a production environment or add a public documentation endpoint.

The document follows the [OpenAPI 3.1 specification](https://spec.openapis.org/oas/v3.1.0.html). It describes stable response cores, permits additive fields, and explains normalization and business rules that are not encoded as JSON Schema. A client must still handle the documented JSON error response. It is not a claim that every possible state, payload, optional branch, or field has been exhaustively exercised.

Authentication uses an opaque Bearer session token, not JWT. Tenant headers select a scope and never grant authority: membership, role, resource ownership and transaction-scoped RLS remain mandatory in the server. Seven owned reads can omit the tenant header and aggregate their authorized memberships; `copilot/read` requires the header for company tools. The synthetic payment webhook instead requires both signed raw-body HMAC and timestamp freshness. Never place a session token, signing secret, real identity, provider credential or production URL in this file.

The existing `scripts/backend-contract-acceptance-e2e.cjs` journey now loads the document through `scripts/openapi-contract.cjs`. Before positive requests it checks documented path/header/body shapes, and after every positive or negative request it checks the real JSON response. Intentional invalid-input/auth probes are not checked against valid-request schemas. The journey still asserts business state, PostgreSQL rows, negative status codes, foreign-tenant invariance, policy invariance and explicit human decisions; a schema check cannot replace those assertions.

The checker deliberately implements only the schema keywords used in this document: local `$ref`, `type`, `properties`, `required`, additive properties, `items`, `enum`, `const`, `anyOf`, numeric bounds, minimum length/items, patterns and date-time. Unsupported schema keywords, remote/recursive references, missing/extra operations, changed controller blobs, security drift and tenant-parameter drift fail closed. This is a bounded integration contract checker, not a general OpenAPI/JSON Schema validator or an independent certification. Changes to controllers require reviewing the document and its source manifest.

The required CI receipt is `OPENAPI_REAL_HTTP_JSON_CONTRACT_PASS`, covering every registered operation and every response observed by that real HTTP/PostgreSQL journey. All pre-existing concurrency, rollback, browser-matrix and Production Truth gates remain required. Local structure checks alone do not count as HTTP/PostgreSQL evidence.

Limits remain explicit: ledger/payment results are simulated; KYC/KYB cases do not prove provider verification; preferences and general support without membership are not implemented. No production, physical-device test, native SecureStore/form rendering, independent pentest, PSP, external contract or real money is asserted. Acceptance of Area 11 requires reconciliation of the full applicable requirements in addition to these API contracts.
